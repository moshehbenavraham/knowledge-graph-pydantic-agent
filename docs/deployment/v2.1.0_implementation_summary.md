## Features Implemented

### 1. 2FA Enforcement System

#### Module: `src/auth/enforce_2fa.py` (350 lines)

**Purpose**: Enforce 2FA requirements for users who need elevated security (e.g., admins).

**Key Functions**:
- `enforce_2fa_if_required(username)` - Main enforcement entry point
- `check_2fa_requirement(username)` - Check if user requires 2FA
- `render_2fa_setup_required()` - Force 2FA setup UI
- `render_2fa_verification()` - 2FA verification UI for login

**Features**:
- Automatic 2FA requirement checking on login (password + OAuth)
- Forced 2FA setup flow with QR code display
- TOTP and backup code verification support
- Session-based verification state tracking
- Seamless integration with existing authentication

**User Flow**:
1. User with `requires_2fa=true` logs in with password/OAuth
2. System checks if 2FA is enabled
   - **Not enabled**: Show setup UI → Generate QR code → Verify code → Generate backup codes
   - **Enabled**: Show verification UI → Accept TOTP or backup code → Continue
3. Session marked as 2FA verified
4. User gains access to application

**Security**:
- Blocks access until 2FA is configured (if required)
- Rate limiting via existing 2FA attempt tracking
- Session state prevents verification bypass
- Encrypted TOTP secrets in database

### 5. OAuth Analytics Database Migration

#### Migration: `src/agentic_rag/storage/migrations/sql/008_oauth_analytics.sql` (350 lines)

**Purpose**: Create materialized views and RPC functions for OAuth analytics.

#### Materialized Views:

**1. `oauth_provider_stats`**
- Summary statistics per provider
- Columns: provider, total_accounts, unique_users, active_accounts, inactive_accounts, avg_age_days, first_linked_at, last_linked_at
- Unique index on provider

**2. `oauth_user_stats`**
- Per-user OAuth statistics
- Columns: user_id, username, email, full_name, linked_accounts, unique_providers, providers[], first_oauth_link_at, last_oauth_link_at, last_oauth_login_at
- Index on user_id

**3. `oauth_login_timeline`**
- Daily login activity by provider (last 90 days)
- Columns: login_date, provider, accounts_logged_in, users_logged_in
- Index on login_date (DESC)

**4. `oauth_account_growth`**
- Daily account linking growth (last 90 days)
- Columns: link_date, provider, accounts_linked, users_linked, cumulative_accounts
- Index on link_date (DESC)

#### RPC Functions:

**1. `refresh_oauth_analytics_views()`**
- Refreshes all 4 materialized views concurrently
- Returns success message
- Security: DEFINER (admin execution)

**2. `get_oauth_provider_summary()`**
- Returns provider statistics from materialized view
- Ordered by total_accounts DESC

**3. `get_oauth_login_activity(days INTEGER)`**
- Returns login activity for last N days
- Default: 30 days
- Parameterized time range

**4. `get_oauth_account_growth(days INTEGER)`**
- Returns account growth for last N days
- Default: 30 days
- Includes cumulative totals

**5. `get_multi_provider_users()`**
- Returns users with multiple OAuth providers
- Ordered by linked_accounts DESC
- Useful for identifying power users

**6. `get_oauth_adoption_rate()`**
- Calculates OAuth vs password vs hybrid user percentages
- Returns metrics with percentages
- 4 rows: Total Users, OAuth Users, Password Only, Hybrid

**Performance**:
- Materialized views for fast queries
- Concurrent refresh for efficiency
- Indexes on frequently queried columns
- 90-day retention for timeline views

**Maintenance**:
```sql
-- Refresh views (manual or cron)
SELECT refresh_oauth_analytics_views();

-- Query provider summary
SELECT * FROM get_oauth_provider_summary();

-- Query login activity (last 30 days)
SELECT * FROM get_oauth_login_activity(30);

-- Query account growth (last 60 days)
SELECT * FROM get_oauth_account_growth(60);

-- Query multi-provider users
SELECT * FROM get_multi_provider_users();

-- Query adoption rate
SELECT * FROM get_oauth_adoption_rate();
```

## Usage Guide

### For Users

#### Viewing 2FA Status (User Profile)
1. Navigate to user profile/settings
2. Look for "🔐 Two-Factor Authentication" section
3. See if 2FA is required/optional and enabled/disabled
4. View backup code count

#### Setting Up 2FA (If Required)
1. Log in with username/password or OAuth
2. If 2FA required but not set up, you'll see the setup screen
3. Scan QR code with authenticator app (Google Authenticator, Authy, etc.)
4. Enter 6-digit verification code
5. Save the 10 backup codes in a safe place
6. Click "Continue to Base Agent"

#### Logging In with 2FA
1. Enter username/password or use OAuth
2. Enter 6-digit code from authenticator app
3. Or enter 8-character backup code (XXXX-XXXX)
4. Click "🔐 Verify"

#### Managing OAuth Accounts (User Profile)
1. Navigate to user profile
2. Find "🔗 Connected Accounts" section
3. See all available providers and link status
4. **To link**: Click "🔗 Link" → Sign in with provider
5. **To unlink**: Click "🔓 Unlink" → Confirm → Done

#### Regenerating Backup Codes
1. Navigate to user profile → 2FA settings
2. Click "🔄 Regenerate Backup Codes"
3. Save the new codes securely
4. Old codes are now invalid

### For Admins

#### Viewing 2FA Management Dashboard
1. Log in as admin
2. Navigate to admin panel (import and call `render_2fa_management_ui()`)
3. See metrics: Total Users, 2FA Required, 2FA Optional
4. View user list with 2FA status

#### Requiring 2FA for a User
1. Open 2FA management dashboard
2. Select user from dropdown
3. View current status and 2FA setup progress
4. Click "✅ Require 2FA"
5. User will be forced to set up 2FA on next login

#### Bulk Requiring 2FA for Admins
1. Open 2FA management dashboard
2. Expand "⚡ Bulk Actions"
3. Click "Require 2FA for all Admin users"
4. All admins without 2FA requirement will be updated

#### Viewing OAuth Analytics Dashboard
1. Log in as admin
2. Navigate to analytics (import and call `render_oauth_analytics_dashboard()`)
3. View overview metrics, provider breakdown, login trends
4. Adjust time range for login/growth charts (7/14/30/60/90 days)
5. Click "🔄 Refresh Data" to update materialized views

#### Interpreting Analytics
- **Provider Breakdown**: Which OAuth providers are most popular?
- **Adoption Rate**: What percentage of users use OAuth vs password?
- **Login Activity**: Are users actively logging in with OAuth?
- **Account Growth**: Is OAuth adoption increasing?
- **Multi-Provider Users**: Who has multiple providers linked?

## Troubleshooting

### 2FA Enforcement Issues

**Problem**: User sees 2FA setup screen but shouldn't
- **Cause**: `requires_2fa=true` set incorrectly
- **Fix**: Check database: `SELECT username, requires_2fa FROM auth_users WHERE username='USER';`
- **Solution**: `UPDATE auth_users SET requires_2fa=false WHERE username='USER';`

**Problem**: QR code doesn't scan
- **Cause**: Authenticator app issue or QR code encoding error
- **Fix**: Use "Can't scan? Enter manually" option
- **Copy**: Base32 secret and enter manually in authenticator app

**Problem**: TOTP codes always rejected
- **Cause**: Time sync issue between server and authenticator app
- **Fix**: Ensure server time is synchronized (NTP)
- **Check**: Server time vs authenticator app time

**Problem**: 2FA verification state lost
- **Cause**: Session state cleared or browser cookies cleared
- **Fix**: User must verify 2FA again (normal behavior)
- **Prevention**: Use "Remember me" checkbox for longer sessions

### OAuth Account Management Issues

**Problem**: OAuth linking fails
- **Cause**: Missing or invalid OAuth credentials
- **Fix**: Check environment variables (GOOGLE_CLIENT_ID, etc.)
- **Verify**: OAuth app redirect URIs match application URL

**Problem**: Provider doesn't appear in list
- **Cause**: Environment variables not set
- **Fix**: Set required credentials in `.env`
- **Example**: `GOOGLE_CLIENT_ID=...`, `GOOGLE_CLIENT_SECRET=...`

**Problem**: Unlink button doesn't work
- **Cause**: Database permission issue or account not found
- **Fix**: Check database logs
- **Verify**: `auth_oauth_accounts` table has record

**Problem**: OAuth callback fails
- **Cause**: State parameter mismatch or expired
- **Fix**: Clear session state and try again
- **Prevention**: Don't open multiple OAuth flows simultaneously

### OAuth Analytics Issues

**Problem**: No data in analytics dashboard
- **Cause**: No OAuth usage yet or views not refreshed
- **Fix**: Click "🔄 Refresh Data" button
- **Or**: Manually refresh: `SELECT refresh_oauth_analytics_views();`

**Problem**: Charts not rendering
- **Cause**: Missing Plotly dependency or empty data
- **Fix**: Install Plotly: `pip install plotly`
- **Verify**: Data exists in materialized views

**Problem**: Slow dashboard performance
- **Cause**: Views not refreshed, querying raw tables
- **Fix**: Refresh materialized views
- **Schedule**: Set up hourly cron job for auto-refresh

**Problem**: Permission denied for analytics
- **Cause**: User doesn't have admin role
- **Fix**: Assign admin role to user
- **Command**: `python -m src.auth.db_cli role --username USER --action assign --role admin`

### Database Migration Issues

**Problem**: Migration 008 fails
- **Cause**: Missing migration 007 or table dependencies
- **Fix**: Apply migrations in order (005, 006, 007, 008)
- **Verify**: `SELECT * FROM auth_oauth_accounts LIMIT 1;`

**Problem**: RPC functions not found
- **Cause**: Function creation failed or not committed
- **Fix**: Re-run migration script
- **Check**: `\df get_oauth_provider_summary` in psql

**Problem**: Materialized views not refreshing
- **Cause**: Concurrent refresh requires unique index
- **Fix**: Verify unique indexes exist on all views
- **Check**: `\d oauth_provider_stats` shows unique index

## Security Considerations

### 2FA Enforcement
- **Threat**: User bypasses 2FA requirement
- **Mitigation**: Session state checked on every request, enforcement before DB session creation
- **Risk**: Low (session state tracked server-side)

### OAuth Account Management
- **Threat**: Unauthorized unlinking of OAuth accounts
- **Mitigation**: Confirmation dialogs, user must be authenticated
- **Risk**: Low (requires authenticated session)

### OAuth Analytics
- **Threat**: Non-admin views sensitive OAuth data
- **Mitigation**: Admin role check before rendering dashboard
- **Risk**: Very Low (role verification enforced)

### Database Security
- **Threat**: SQL injection in RPC functions
- **Mitigation**: Parameterized queries, SECURITY DEFINER functions
- **Risk**: Very Low (PostgreSQL prevents SQL injection in RPC parameters)

### Session Management
- **Threat**: Session hijacking to bypass 2FA
- **Mitigation**: Streamlit cookie authentication + DB session tokens
- **Risk**: Low (existing session security)
