## Database Tables Summary

### auth_users
- **Purpose**: Core user authentication and profiles
- **Key Fields**: username, email, password_hash, full_name, is_active, locked_until
- **Indexes**: username, email, is_active, created_at

### auth_sessions
- **Purpose**: Track active user sessions
- **Key Fields**: user_id, session_token, device_info, expires_at, revoked_at
- **Indexes**: user_id, session_token, expires_at

### auth_password_reset_tokens
- **Purpose**: Temporary tokens for password reset
- **Key Fields**: user_id, token, token_hash, expires_at, used_at
- **Indexes**: user_id, token, expires_at

### auth_oauth_accounts
- **Purpose**: Link OAuth provider accounts
- **Key Fields**: user_id, provider, provider_user_id, access_token, profile_data
- **Indexes**: user_id + provider, provider + provider_user_id

### auth_roles + auth_user_roles
- **Purpose**: Role-based permissions
- **Default Roles**: admin (full access), user (standard), viewer (read-only)
- **Indexes**: role_name, user_id + role_id

## CLI Tools Reference

### User Management
```bash
# Create user
python -m src.auth.db_cli create --username USER --email EMAIL --name NAME --password PASS --role ROLE

# List users
python -m src.auth.db_cli list [--limit N] [--include-deleted]

# Get user details
python -m src.auth.db_cli get --username USER

# Update user
python -m src.auth.db_cli update --username USER [--new-username] [--new-email] [--new-name] [--activate|--deactivate]

# Update password
python -m src.auth.db_cli update-password --username USER --new-password PASS

# Delete user
python -m src.auth.db_cli delete --username USER [--permanent]

# Assign/revoke role
python -m src.auth.db_cli role --username USER --action {assign|revoke} --role {admin|user|viewer}

# View/revoke sessions
python -m src.auth.db_cli sessions --username USER [--revoke]
```

### Migration
```bash
# Dry run
python -m src.auth.migrate_yaml_to_db --dry-run

# Actual migration
python -m src.auth.migrate_yaml_to_db

# Custom config path
python -m src.auth.migrate_yaml_to_db --config /path/to/auth_config.yaml

# Skip backup
python -m src.auth.migrate_yaml_to_db --no-backup
```

## Security Features

### Implemented
- ✅ **Bcrypt password hashing** (12 rounds)
- ✅ **Rate limiting** (5 attempts / 15 min lockout)
- ✅ **Session expiration** (30 days + idle timeout)
- ✅ **Secure token generation** (secrets.token_urlsafe)
- ✅ **Password strength validation** (8+ chars, mixed case, numbers, special)
- ✅ **Account lockout** (automatic, time-based)
- ✅ **Audit logging** (all auth events to analytics)
- ✅ **Soft delete** (users not permanently deleted by default)
- ✅ **IP tracking** (login attempts, password resets, session creation)

### Recommended for Production
- ⚠️ **HTTPS only** (set `cookie.secure: true` in auth_config.yaml)
- ⚠️ **Rotate AUTH_COOKIE_KEY** monthly
- ⚠️ **Enable Supabase RLS** policies
- ⚠️ **Monitor failed login analytics**
- ⚠️ **Regular session cleanup** (cron job)

## Rollback Plan

If issues arise, rollback is simple:

1. **Switch to YAML mode**:
   ```bash
   # In .env
   USE_DATABASE_AUTH=false
   ```

2. **Restart application**:
   ```bash
   make run-ui
   ```

3. **Restore YAML backup** (if needed):
   ```bash
   cp config/auth_config_backup_<date>.yaml config/auth_config.yaml
   ```

Application will immediately fall back to YAML authentication with zero data loss.
